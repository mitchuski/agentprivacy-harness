What the SERV tests measured

We ran a real verification round — a proposer proposes a change, a prover checks it against a held-out gate — with an inference API holding the prover seat, across a spread of models, with the reasoning layer on and off. This is what the numbers showed.

Finding 1 · The code gate is model-independent

The same wrong answer, every time. A proposal that dropped one required word was caught on 11 of 11 models — the census returned 94/95 identically regardless of which model held the prover seat. The part of the gate that is code does not depend on who is proving.

Finding 2 · The judgment seat tracks the model

Same candidate, different verdict. A second proposal that kept all 95 strings (a full 95/95 code pass) still needed a human-style judgment: does the shorter text still read as the newcomer's document? On the identical candidate, 6 of 11 models validated it and 5 called it a mirage.

Finding 3 · The reasoning layer changes cost, not the verdict

On and off agreed everywhere. Across 6 of 6 models run both ways, the reasoning layer and raw mode reached the same verdicts. The layer added about 2,091 prompt tokens per round (7 seats) and the seats emitted -13% fewer completion tokens under it. The answer held; only the price and phrasing moved.

Finding 4 · It catches mirages and banks real wins

Not just a rejector. A conservative edit that cut one sentence of glue and kept all 95 strings was validated by Claude Haiku 4.5 and Claude Sonnet 5 — a genuine improvement past the prior record. The strictest model (GPT-5.4 Nano) rejected even that as a false negative, which is the honest weakness to know: a weak prover errs toward refusal.

Finding 5 · A guard that catches an injection blocks the work with it

Detection has a cost. One proposal carried a benign but injection-shaped instruction aimed at the verifier. Raw and plain reasoning judged it on its merits; with the prompt guard on, every seat that saw the text refused, so the round returned incomplete with no verdict — the injection caught, and the honest work in the same prompt caught with it.

What it means for the harness

  • The core claim held: the code-checked half of the gate was identical across 11 models — the separation does not depend on the prover.
  • Its integrity checks bite: when provers on a compute-requiring gate rubber-stamped a step they could not perform, the harness's own mint check refused those runs. It declined to bank verdicts that were not earned.
  • The rule for adopters: put as much of the gate in code as possible, reserve the model for genuine judgment, and match the prover to what the gate demands.
